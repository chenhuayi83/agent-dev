# 规划与推理

agent 如何决定做什么:ReAct、plan-and-execute、reflection/self-critique、extended thinking(推理预算)、以及无显式规划的"model 即 planner"路线。

## 原理(稳定)

### generator-verifier gap:所有推理范式的共同骨架

ReAct、Plan-and-Execute、Reflection/Reflexion、Tree-of-Thoughts 本质上都是**搜索算法**——差别只在搜索树的形状和什么时候剪枝。既然是搜索,决定成败的就不是"能不能生成候选"(生成很便宜),而是**能不能挑对**。这就是 generator-verifier gap:

- **有可靠验证器时**(测试能跑、编译能过、结果可对账):多生成几个候选几乎稳赚,采样次数越多越好——验证器负责挑,错误不会累积;
- **没有验证器时**:自我批评(self-critique)与生成器共享同一套先验和同一段上下文,它挑不出自己看不见的错。此时增加采样只会产生**更自信的错误答案**。

由此得到选型的 2×2:**错误代价 × 可验证性**。最需要警惕的格子是"错误代价高 + 无验证器"——那里该做的不是加范式、加采样,而是**造验证器**(写测试、找对账口径、引入人审),否则所有推理范式都只是在增加成本与幻觉的自信度。

推论:**范式选择的本质是"用更多推理与轮次换正确率"**,只有当换来的正确率能被验证时,这笔交易才成立。

### 哪些被模型内化了,哪些没有

拆开看会发现内化是**按层**发生的,不是整体淘汰:被内化的是"认知动作"(边想边做、先规划、自我检查——模型原生会了);没被内化的是"工程属性"——外部信号的接入、人的介入时机、跨会话的持久化。所以今天仍需显式实现的,基本都是后者。
