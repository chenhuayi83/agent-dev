# 检索与 Agentic Search

从静态 RAG 到 agentic search:让 agent 主动 grep/glob/语义检索,检索工具设计、结果注入格式、与长上下文的取舍。

## 原理(稳定)

### 漏斗式误差相乘

RAG 是一条串联流水线(切分 → 嵌入 → 检索 → 重排 → 生成),每级的召回率**相乘**得到端到端质量。这决定了排障顺序:**先定位是哪一级掉的,再优化那一级**——在生成端调提示词救不回检索端丢掉的文档。常见的错误归因是把"答不对"当成模型问题,实际大多数是切分或检索问题。

### 两段式检索:为什么需要 rerank

bi-encoder(向量检索)把 query 与 doc **各自独立**编码成向量,因此可以离线建索引、在线只做近邻搜索——快,但 query 与 doc 从未"见过面",语义交互被压进了一个点积。cross-encoder(rerank)把 query 与 doc **拼在一起**过一遍模型,能建模细粒度交互——准,但无法预计算,只能对候选集做。

于是标准结构是**先召回后精排**:bi-encoder 取 top-50(保召回),cross-encoder 精排到 top-5(保精度)。这不是叠加两个模型,而是用便宜的一级换搜索空间、用贵的一级换排序质量。

### 上下文补全:切碎会丢掉指代

切分的根本损失是**块脱离了原文语境**(代词、隐含主语、章节前提)。Anthropic 的 Contextual Retrieval 做法是:在嵌入前给每个块**拼上一段由模型生成的、说明该块在全文中位置与含义的上下文**,再嵌入与索引。这直接攻击的是"块本身语义不完整"这一切分的固有缺陷。

## 现状(as-of 2026-08-19,核实于面试题 11 组撰写)

- **Contextual Retrieval 效果口径**(Anthropic 官方):在 top-20 检索设定下,检索失败率相对下降约 35%;叠加 BM25 混合检索后约 49%;再加 rerank 约 67%(数值为官方博客口径,非独立复现)
- **何时不要建 RAG**:官方给出的经验阈值是——**知识库小于约 200K token 时,直接把全部内容放进上下文通常优于建 RAG**(省掉整条流水线的误差与运维成本)
- **成本量级之争**(厂商博客口径,仅作数量级参考):有观点主张检索比长上下文全量投喂便宜 8–82×;该类数字随模型定价与缓存策略剧烈变化,引用须标口径
- **多模态边界**:"你没法 grep 一张图"——图表、扫描件、版式信息无法靠文本检索命中,这是 agentic search 无法取代向量/多模态检索的硬边界
